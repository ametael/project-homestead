# Memory and privacy

Use `MEMORY/INDEX.md` for durable shared decisions, explicit shared preferences and cross-project facts. Keep project detail in the owning project. Keep a persona's private experiences under that owner's `MEMORY/PRIVATE/` inside their persona slot. Keep the user's facts distinct from the persona's identity and ask before retaining sensitive personal information.

Open the relevant index and only the authorized note. Never expose private filenames, summaries, or derived details in shared indexes, checkpoints or public templates. An owner declaration or Git ignore rule does not enforce access restrictions. Shared folders and cloud hosts need permissions appropriate to the user's actual sharing intent.

Record what the user provided or what can be evidenced, with date and source when useful. Preserve corrections and original meaning. Skip routine, duplicate, speculative or passing material. Save and verify meaningful updates only within scope. Follow [Files and Git](FILES_AND_GIT.md) before writes.

## Inbox

Use `MEMORY/INBOX/` for new shared items and the selected owner's `MEMORY/PRIVATE/INBOX/` within their persona slot for private material. Copy the [inbox index template](../TEMPLATES/INBOX_INDEX.md) into either inbox when needed. Check only authorized metadata and read a body's contents only when the task, owner and permission match. Keep originals and record where accepted material was routed. If ownership is unclear, leave the item for the user's direction. A new chat does not automatically process the inbox.
